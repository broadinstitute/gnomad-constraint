Synonymous-DNM regional mutation rate (rr) in the coding constraint pipeline

2026-10-16 · gnomAD v4.1.1 per-variant expected · 18,406 Ensembl MANE Select transcripts (autosomes and chrX/Y) · LOEUF deciles from v4.1.2

Code: gnomad-constraint branch rp/add_mu_adjustment (not yet pushed), commit dfb578c plus the uncommitted --compare-rr-variants step. Main files: gnomad_constraint/utils/regional_rate.py, gnomad_constraint/pipeline/regional_rate_pipeline.py, prepare_syn_dnms.py, build_xy_features.py, and utils/constraint.py (annotate_regional_rr_expected). Follows up adj_r_investigation_report.html.

Summary

  • The port is exact, and rr is applied after calibration. Given the notebook's training data, the pipeline reproduces syn_adj_r to within 5×10⁻¹³. Expected counts are multiplied by rr only when per-variant expected counts are aggregated; the plateau and coverage models are read unchanged.
  • Retrained on the combined synonymous DNM set, the new rr is close to legacy syn_adj_r but slightly weaker. With the overall level removed, dispersion is 4.45 for the new rr and 4.37 for legacy, against 5.08 with no correction. Outliers are about the same (214–219 for the new rr vs 213–219 for legacy, from 254–270 with no correction). The gap comes from the training set, not the code.
  • Normalization only changes the overall level, not the noise. Raw rr averages about 1.014 over exome synonymous sites, so it raises every gene's expected by about 1.4%. That makes raw dispersion look 0.12 lower, but with the level removed raw and normalized rr are the same (legacy 4.378 vs 4.373; new 4.455 vs 4.447). Without normalization, synonymous obs/exp in constrained genes (LOEUF deciles 0–5) drops to 0.986–0.998. Normalization should stay on.
  • Clipping to [0.2, 5] has no effect: almost no window falls outside that range.
  • chrX/Y: rr helps slightly unmasked, and masking removes that. Over 769 chrX/Y transcripts, level-free dispersion is 4.36 with no correction, 4.33 with unmasked rr, and 4.43 with masking. Legacy has no chrX/Y rr.
  • The Bonferroni cutoff (the legacy rule) remains the best feature-selection cutoff. Looser cutoffs model more contexts but add noise and halve the held-out DNM likelihood gain.
  • Both rr versions are about 25–30% too strong in coding sequence. Their calibration slopes are 0.68 (new) and 0.75 (legacy), and dispersion is lowest at about 0.75 strength. The non-coding adj_r used in PR #55 is about 3–4× too strong (slope 0.28) and inflates expected counts by about 9%.
  • These results settle the synonymous comparison. The constraint pipeline still has to be run for LoF and missense metrics (LOEUF, pLI, flags); see the last section.

Background

  • rr is Gnocchi's regional mutation-rate ratio (Chen et al. 2023, atgu/gnomad_nc_constraint). For each of the 32 strand-collapsed trinucleotide contexts, a logistic model separates de novo mutation (DNM) sites from non-mutated sites using 13 regional genomic features, each at 4 flanking scales (1 kb–1 Mb). For a 1 kb window, rr = σ(β₀ + β·z(x)) / σ(β₀): the model's DNM probability for the window relative to the average window. Expected counts are multiplied by rr.
  • Legacy tables (gs://gnomad/v4.1/constraint/resources/annotations/ht/):
    • adj_r: Gnocchi's released models, trained on genome-wide (mostly non-coding) DNMs.
    • syn_adj_r: the same machinery refit on synonymous DNMs in syn_dnm_adj_r_methods.ipynb. It has models for 12 of 32 contexts and covers autosomes only.
  • What the previous report found: adj_r is scaled to the genome while our expected counts are calibrated on the exome, so it over-scales coding sites by about 11%, and it is also about 4× too strong there. syn_adj_r was well calibrated but covered only 12 contexts and was built by hand.
  • This work builds syn_adj_r into the pipeline, applies it per variant after model calibration, extends it to chrX/Y, and makes the feature-selection cutoff tunable. This report compares each change against legacy syn_adj_r on the same exome synonymous data.

Data and metrics

  • DNMs: 17,735 synonymous DNMs across cohorts (DDD+ASD 14,283, deCODE+PsychENCODE 1,876, CHD 642, gnomAD v4.1 430, CDH 228, OFC 193, EE 83). Deduplicating removes 676 sites reported by two or more cohorts (652 are shared by DDD+ASD and deCODE+PsychENCODE, which share samples), leaving 17,059 unique DNMs. That is the same variant set as the notebook's input (0 differences). 202 are on chrX and none on chrY. The notebook dropped chrX and kept the duplicates.
  • Training set: 17,059 DNMs and 479,021 background sites, versus 17,533 DNM rows (with duplicates) and 459,612 background sites for legacy.
  • Features: the published 13-feature 1 kb matrix (chr1–22) plus the new chrX/Y matrix (213,267 windows). On chrX/Y, 7 of the 13 features have source data; the other 6 are missing.
  • Evaluation set: synonymous sites of 18,406 Ensembl MANE Select transcripts in the v4.1.1 per-variant expected table. For each transcript, adj observed is compared with unadjusted expected × rr, with rr = 1 where a site has no window or the context has no model. This is the same calculation the pipeline's aggregation step performs.
  • Metrics:
    • Raw dispersion: mean z² over all transcripts, where z = (obs − exp)/√exp.
    • Outliers: |z| > 8.
    • Level-free dispersion: each variant's expected counts are first rescaled so overall obs/exp = 1, so this measures noise only. The core set is the 17,032 unflagged transcripts with expected ≥ 20, the previous report's Test 9 definition.
    • Calibration slope: the previous report's Test 8, on 16,458 unflagged transcripts with expected ≥ 50. It is the log-log slope of uncorrected obs/exp against the gene's mean rr; 1 means rr matches the observed variation exactly.
    • o/e by LOEUF decile: fixed v4.1.2 LOEUF deciles.
    • Absolute values differ from the previous report's (for example its no-correction dispersion of 2.58), which used v4.1.2 expected counts on autosomal transcripts only, so compare variants within this report.
  • How the variants are built: regional_rate_pipeline.py --compare-rr-variants builds each variant from the trained models with the same code as --compute-rr, so each change can be switched on separately.

2. Normalization

Expected-weighted mean rr over exome synonymous sites, by context. These are the factors that normalization divides by. Only contexts with a model in either version are shown; the rest are exactly 1.

  • Both versions average above 1 in coding sequence (legacy 1.011, new 1.014 per gene), most for ACC, GCT, and TCT (up to 1.09). The non-coding adj_r averages 1.094 (up to 1.32 for CCC). Our expected counts are already calibrated on exome synonymous sites, so this excess counts the exome's above-average rate twice.
  • Raw rr looks better only because of the overall level. Uncorrected obs/exp is above 1 overall (1.015; 1.011 among unflagged genes with expected ≥ 20), mostly because of the least-constrained genes. Raw rr's roughly 1.4% increase brings the average to about 1 (1.001 and 0.998). But it is nearly the same for every gene, so it does this by pushing constrained genes below 1 (section 3), and the level-free numbers show it removes no extra noise. An overall offset like this belongs in the model calibration, not in rr.
  • Normalization keeps constrained genes at 1 (next section), and it keeps LoF and missense expected counts at the level the models were calibrated to. Without it, LoF expected would also rise by about 1.4% and shift LOEUF for every gene.

Do the downstream constraint steps need to be run?

  • Not for the synonymous comparison. These metrics use the same per-variant expected counts and the same per-variant × rr multiplication that --aggregate-per-variant-expected uses (check 5 confirms the pipeline gives the same numbers). Running the constraint pipeline wouldn't change any synonymous conclusion here.
  • Yes, for everything else. rr also changes LoF and missense expected counts, so LOEUF and its ranks and deciles, pLI, missense and LoF z-scores, the outlier flags, and the sd_raw_z scaling all need the full run (--aggregate-per-variant-expected through --prepare-release). LOEUF-based checks, such as how well LOEUF still separates haploinsufficient genes, need those outputs.
  • A separate no-rr run isn't needed: the release keeps the unadjusted results in unadj, which equal a no-rr run exactly (check 5).
  • Settle the open choices first (chrX/Y masking, and possibly rr strength), so the full run is done once with the final rr table.

Conclusions

  1. The code is correct. It reproduces legacy syn_adj_r exactly on legacy inputs, and rr is applied after calibration without touching the models.
  2. The new rr matches legacy closely and adds chrX/Y and a tunable cutoff. It is slightly less effective (about 90% of legacy's noise reduction) because of the new training set.
  3. Normalization is right and costs nothing in noise. Its apparent cost in raw dispersion is a 1.4% overall offset that would otherwise also shift LoF and missense expected counts.
  4. chrX/Y masking hurts. Unmasked rr is slightly better than none on chrX/Y; masked rr is worse.
  5. Both synonymous rr versions are about 25–30% too strong in coding sequence; the non-coding adj_r is about 3–4× too strong.

Possible next steps

  • Drop chrX/Y masking: rebuild the default table with --compute-rr --apply-rr-safeguards without --mask-features, and run the constraint pipeline without --regional-rr-xy-masked.
  • Close the gap to legacy: retrain with a larger background (for example --background-fraction 0.2) to test whether the gap is sampling noise.
  • Consider fitting a strength: rrα with α fit on exome synonymous sites (about 0.75 here), applied before normalization.
  • Then run the constraint pipeline once with the final rr, and compare LOEUF, its deciles, pLI, and outlier flags against unadj.
